# GBAX SDK v1 — phase 8A

Copy sdk/gbax.h and include/mgba/internal/gba/gbax-abi.h next to one another in the guest include directory. No runtime library, heap, libc or OS needed. Compile for ARM7TDMI using C99. The header is an API for explicitly marked GBAX ROMs, not a generic replacement for malloc or the pokeemerald allocator.

Read-only 32-bit discovery registers 0x44000020..0x44000038: magic, signature, ABI version (major in high 16 bits), capability bits, work RAM bytes, ROM128 actual file bytes (0 if absent), current compute multiplier. On unmarked ROMs detection fails without writing to the bus. Check GBAXDetect before any extended access; check GBAXHas for optional features. A marked ROM must have the existing title/game-code marker at 0xA0: GBAX RAM64  GBAX, fixed header byte 0x96 at 0xB2 and valid header checksum. HLE/skip BIOS is recommended for original diagnostic code. Existing commercial game assets are not included.

Memory ownership: create exactly one root GBAXArena, reserve non-overlapping child arenas (e.g. Genesis, Nemesis, raids), use GBAXAlloc with alignment and bounded rewind. The root excludes SAVX staging: 48 MiB at 0x40000000..0x42FFFFFF; 16 MiB at 0x43000000..0x43FFFFFF for explicit load/commit. Arena metadata must be owned by the game and reset/reinitialized consistently; allocation does not clear previously used bytes. No automatic migration, no native malloc replacement, no free-list, no IRQ safety. Rewind only a checkpoint belonging to that arena; rewinding a parent invalidates all children allocated after that point.

GBAXAsset validates file offset and length against actual ROM128 file size; returns a data pointer only. GBAXCopy32 uses immediate DMA3 for up to 65536 aligned words with nonoverlapping bounded ranges. Caller owns DMA3, including IRQ handlers; use repeated transfers for larger copies. No VRAM/OAM or MMIO transfers exposed by this conservative helper. Native RAM ranges restricted to actual EWRAM/IWRAM. SAVX load returns EMPTY or LOADED, commit returns COMMITTED; other statuses are errors/unavailable. Do not commit unless payload serialized correctly; staging is overwritten on LOAD. Never use SAVX as ordinary scratch. Save identity remains exact ROM CRC, so upgrading a ROM requires a migration solution not yet implemented. CPU multiplier is informational, not a game-controlled setting.

Native CI compiles an original C diagnostic on ARM7TDMI, exercises detection, arena isolation, bounds, DMA and ROM128 data, then loads/commits SAVX and verifies persistence after core destruction and reload. An unmarked copy checks detection failure. No Unholy files or current saves are changed. SDK integration into pokeemerald-expansion, asset packaging, stable save identity, and Android physical QA are next.
